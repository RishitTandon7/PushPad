How it works

Six steps from git push to a URL you can share.

  1. 01

    Push

    You push a branch to GitHub.

    Git
  2. 02

    Webhook

    GitHub pings Jenkins, which starts a build.

    GitHub
  3. 03

    Test

    Lint and unit tests must pass or the build stops.

    Jenkins
  4. 04

    Package to S3

    The app is zipped with its dependencies and uploaded.

    AWS S3
  5. 05

    Terraform Apply

    A fresh EC2 boots from the zip in its own workspace.

    Terraform
  6. 06

    Health Check

    Jenkins checks /health and /version, then shares the URL.

    Jenkins

Features

Everything a real platform does, small enough to explain.

  • 01

    Branch previews

    One temporary EC2 and URL per branch.

  • 02

    Auto-destroy on merge

    Delete the branch and its server disappears within minutes.

  • 03

    Prod approval gate

    Main waits for a human click before touching prod.

  • 04

    Auto rollback

    A failed health check re-deploys the last good build.

  • 05

    Remote state with locking

    Terraform state lives in S3 and cannot be applied twice at once.

  • 06

    Cost guard

    Previews older than 24 hours are destroyed automatically.

FAQ

What is PushPad?

A self-hosted mini Vercel. Pushing a Git branch makes Jenkins build it and Terraform create a real EC2 server with its own URL.

How is it different from ngrok?

ngrok tunnels your laptop to the internet. PushPad builds real cloud servers that keep running without your laptop.

How are previews destroyed?

A cleanup job runs every 5 minutes, compares Terraform workspaces with the branches on GitHub, and destroys any workspace whose branch is gone.

What does it cost?

Almost nothing: one EC2 for Jenkins, one for prod, and previews that live minutes. Previews older than 24 hours are removed automatically.

How does rollback work?

Before each prod deploy the last good build is saved. If the new build fails its health check, Terraform re-applies the saved build and the pipeline fails loudly.

Can it deploy non-website apps?

Yes. Anything that runs on Linux and can be zipped can be started by the same systemd service, for example an API or a worker.
