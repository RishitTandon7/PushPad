01 / What it is
What is PushPad?

        
    
          
  • Before
    The problem
    Testing a branch normally means setting up a server by hand.
    • 
          
  • Now
    What PushPad does
    It builds a temporary server for each branch, automatically.
    • 
          
  • After
    What you get
    A live link to share, and nothing left running after you merge.
    • 
        

        
Think Vercel preview deployments, self-hosted on your own AWS with Jenkins and Terraform.

04 / Deploy
Deploy your own project

        
    
          
  1. 01
    Get the code
    Fork or clone the PushPad repo.
    
            
    git clone https://github.com/RishitTandon7/pushpad.git
    2. 
          
  2. 02
    Add your app
    Put your app in the app/ folder. Any Node app works if it has npm start and a /health route.
    
            
    cd pushpad/app
npm start
    3. 
          
  3. 03
    One-time setup
    Create the Jenkins server and AWS pieces once, following docs/SETUP.md.
    
            
    sudo ./scripts/bootstrap-jenkins.sh
    4. 
          
  4. 04
    Push a branch
    Create a branch and push it. Open the URL Jenkins prints.
    
            
    git checkout -b my-feature
git push -u origin my-feature
    5. 
        

        
PushPad is self-hosted. It deploys branches of the repo it is connected to; it is not a public hosting service.

06 / FAQ
Questions

        

          
A self-hosted mini Vercel. Pushing a Git branch makes Jenkins build it and Terraform create a real EC2 server with its own URL. ngrok tunnels your laptop to the internet; PushPad builds real cloud servers that keep running without your laptop.

          
A cleanup job runs every 5 minutes and destroys any server whose branch is gone, plus any preview older than 24 hours. You pay for one Jenkins server, one prod server, and previews that live minutes.

          
Before each prod deploy the last good build is saved. If the new build fails its health check, Terraform re-applies the saved build and the pipeline fails loudly.

          
Yes. Anything that runs on Linux and can be zipped can be started by the same systemd service, for example an API or a worker.
